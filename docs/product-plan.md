# 抖音水果商家增长 Agent 商用计划

> 状态：方案已确认，尚未开始代码实现  
> 保存日期：2026-07-18  
> 目标市场：抖音电商中小水果商家

## 1. 产品概要

打造面向中小水果商家的国内云 SaaS 工作台，用统一知识库串联：

**短视频获客 → 飞鸽咨询 → 商品推荐 → 售后处理 → 效果复盘**

- 首版定位：客服副驾、短视频策划、增长复盘。
- 自动化边界：所有回复、内容和经营动作先由人工确认。
- 禁止自动执行：退款、赔付、改价、改库存、自动发布。
- 接入策略：首版使用 Excel/CSV、表单和复制粘贴；取得抖店权限后切换正式连接器。
- 商业模式：单店 6–8 周项目制试点，标准报价 ¥39,800。
- 核心验收：咨询到支付转化率相对基线提升至少 15%。

## 2. 产品与技术底座

- 管理端：Next.js 16.2。
- 后端：FastAPI 0.139、Python 3.12。
- 数据库：PostgreSQL 18.4、pgvector 0.8.2。
- 基础设施：托管 Redis、境内对象存储、国内云部署。
- 架构：模块化单体，按商家进行逻辑租户隔离。
- 安全：数据库行级权限控制、敏感字段加密、全量审计日志。
- 角色：老板、运营、客服、实施管理员。
- 模型网关：支持境内模型供应商切换、结构化输出、脱敏、超时、重试、备用模型、成本统计和审计。
- 模型选择：在事实错误率低于 2%、高风险召回率至少 95% 的前提下，选择成本最低的合格模型。

## 3. 商家知识中心

支持录入和维护：

- 商品、SKU、品种、产地、果园。
- 口感、成熟度、规格、净重。
- 库存、价格、发货区域、物流时效。
- 保存与食用方法。
- 坏果举证、赔付和售后政策。
- 产地故事、FAQ、优秀客服话术。

每条知识必须包含来源、负责人、更新时间、有效期和审核状态。

行为规则：

- 商品、库存、价格、物流等结构化事实采用精确查询。
- 产地故事、FAQ 和话术采用语义检索。
- 库存、价格或发货时效过期时禁止推荐。
- 知识冲突时展示冲突来源并转人工，不允许模型猜测。
- 导入失败时逐行返回字段、原因和修复建议，不允许脏数据静默写入。

## 4. 飞鸽客服副驾

客服粘贴顾客消息后，系统需要：

1. 识别购买意图、售前/售后阶段和风险等级。
2. 查找关联商品、SKU 和可信知识。
3. 返回最多三条可编辑回复建议。
4. 每条建议展示推荐 SKU、事实依据、置信度和风险提示。
5. 记录原始建议、人工修改、采纳状态、响应耗时、成交和售后结果。

覆盖场景：

- 口感、规格、产地、成熟度。
- 自用、送礼与人群偏好。
- 到货时间、保存方法。
- 坏果举证与政策内赔付流程。
- 售前推荐、物流查询和基础售后。

必须转人工：

- 健康、过敏或疾病相关问题。
- 食品安全问题。
- 批量坏果或可能形成舆情的问题。
- 投诉监管、超政策赔付、退款争议。
- 人身损害或知识冲突。

首版不自动读取或发送飞鸽消息。正式资质获批后，才允许灰度启用飞鸽连接器。

## 5. 短视频运营 Agent

根据产季、库存、商品卖点、顾客高频问题和历史内容表现生成周内容计划。

每条内容包含：

- 选题和目标人群。
- 前三秒钩子。
- 完整口播稿。
- 分镜和拍摄清单。
- 标题和封面文案。
- 行动引导。
- 合规风险与修改建议。

首版限制：

- 不自动生成虚假水果画面。
- 不自动剪辑。
- 不自动发布。
- 不允许无法证明的产地、甜度、功效、价格或稀缺性承诺。

商家可记录拍摄状态、发布时间、播放量、互动量、进店和成交表现，作为下一周期优化依据。

## 6. 核心领域接口

### MerchantKnowledge

租户、知识类型、内容、来源、负责人、更新时间、有效期、审核状态。

### ProductSKU

商品、SKU、规格、价格、库存、销售区域、数据更新时间。

### ConversationCase

匿名会话、售前/售后阶段、用户意图、关联商品、风险等级。

### AgentSuggestion

结构化回复、引用依据、推荐 SKU、置信度、风险提示、审批状态。

### ContentBrief

选题、脚本、分镜、拍摄清单、合规结果、发布和效果数据。

### OutcomeEvent

建议采纳、支付、退款、投诉、内容发布及指标归因。

### CommerceAdapter

统一提供商品、SKU、订单、售后和会话事件读取能力。

### ManualImportAdapter

负责首版 CSV、表单和人工结果录入。

### DouyinShopAdapter

获得平台权限后实现 OAuth、消息验签、事件去重、幂等、限流、接口费用统计和权限降级。

正式连接器以抖店官方已开放的商品、订单、库存、售后和消息能力为边界，不承诺未获准的全自动客服。

## 7. 实施顺序

### 第 1–2 周

- 多租户、成员与权限。
- 操作审计。
- 模型网关。
- 商家知识模型。
- CSV/Excel 导入。

### 第 3–4 周

- 知识检索。
- 客服副驾。
- 引用与新鲜度判断。
- 风险转人工。
- 建议采纳和结果记录。

### 第 5–6 周

- 短视频运营 Agent。
- 内容日历。
- 合规检查。
- 内容审批。

### 第 7 周

- 增长看板。
- 指标归因。
- 模型成本、延迟和质量监控。

### 第 8 周

- 安全加固。
- 商家知识校准。
- 使用培训。
- 历史基线。
- 首批商家上线。

### 上线后 6–8 周

- 对照试验。
- 每周复盘。
- 提示词和知识优化。
- 商业验收。

抖店资质申请与产品开发并行，权限未获批不得阻塞手工版交付。

## 8. 测试与验收

### 自动化测试

- 导入格式和逐行校验。
- 知识有效期与冲突处理。
- 风险分类与转人工。
- 事实引用。
- 敏感信息脱敏。
- 租户隔离和权限控制。
- 模型故障切换和任务重试。
- 重复事件幂等。
- 权限失效降级。
- 数据导出与删除。

### Agent 评测

建立至少 100 条真实且匿名化的水果客服案例，覆盖：

- 售前咨询。
- 商品推荐。
- 物流。
- 坏果。
- 退款。
- 投诉。
- 健康与食品安全问题。

### 性能目标

- 普通客服建议 P95 在 8 秒内返回。
- 失败后 15 秒内展示降级结果或明确转人工。

### 商业验收

- 咨询到支付转化率相对基线提升至少 15%。
- 建议采纳率至少 70%。
- 首响耗时下降至少 30%。
- 事实性错误率低于 2%。
- 高风险转人工召回率至少 95%。
- 退款或投诉率不得劣化超过 1 个百分点。
- 每周至少生成 15 个可拍脚本。
- 商家内容发布率至少 40%。
- 不得出现严重合规或跨租户数据事件。

## 9. 商业交付

标准试点项目价格：**¥39,800**

包含：

- 一个抖音店铺。
- 最多十名成员。
- 一次知识整理与导入。
- 系统配置和培训。
- 6–8 周试点。
- 每周复盘和最终验收报告。

付款节点：

- 合同签署：50%。
- 试点上线：40%。
- 验收完成：10%。

不包含：

- 抖店接口费用。
- 广告投放费。
- 真人拍摄与自动剪辑。
- 自动发布。
- 开放平台资质保证。
- 无限范围定制。

试点完成后，根据实际模型成本和使用量制定订阅价格，首版不建设复杂计费系统。

## 10. 安全与合规边界

- 个人信息采用最小必要、默认脱敏和境内存储。
- 地址、电话等订单敏感信息不得进入模型提示词。
- 商品、经营主体和售后信息必须真实、准确、及时。
- 不得把普通水果描述成具有治疗、预防疾病或保健功效。
- 不得生成虚假产地、甜度、价格、稀缺性或赔付承诺。
- 商家负责审核和最终发送客服回复、发布营销内容。
- 产品不替代法律、食品安全或医疗专业判断。
- 严重事件仅进行识别、留痕和转人工。
