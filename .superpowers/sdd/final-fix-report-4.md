## Security design

### No model free text across the output boundary

- `CopilotService` never reads `draft.suggestion_text` or `draft.risk_tip`.
- `original_text` is assembled exclusively from server templates, the fresh
  tenant-scoped `ProductSKURead` snapshot, and an optional approved knowledge
  excerpt.
- `risk_tip` is generated by a fixed policy over controlled case risk, status,
  intent, and conflict reason. Model-authored tips are discarded.
- A direct database regression proves a model's false price and
  `wxid_attacker123` are absent from `copilot_suggestions`, API creation output,
  and history.

### Complete shipping fact equality

- `shipping_eta` has no Pydantic default. Providers must include the field,
  while its value may be null.
- The service always normalizes and compares claim and SQL values. Value/null,
  null/value, and differing values reject the complete generation.
- SQL null plus claim null and equal non-null values are covered by successful
  suggestion tests.

### Deterministic relevant rendering

- Stage contributes the fixed `售前`/`售后`/`服务` label.
- Delivery uses SQL `sales_regions` and `shipping_eta`.
- Storage uses SQL ripeness/specification and may append an approved storage
  knowledge excerpt.
- Gift uses SQL specification, net weight, origin, and taste.
- Product information uses SQL variety, orchard, price, inventory, origin, and
  net weight.
- Recommendation uses SQL variety, taste, specification, price, inventory,
  origin, and net weight.
- Knowledge comes only from the current tenant's approved, unexpired semantic
  result set, and only when its ID is explicitly referenced by the validated
  draft. Whitespace is normalized and each excerpt is capped at 500 characters.
- All drafts are validated before de-duplication. Invalid duplicate evidence
  therefore still fails closed; only display duplication is removed.
